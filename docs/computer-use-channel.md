# Computer Use 通道修复与验证

微信通道执行 Windows 界面任务时，通过本机 Codex App Server 的 `node_repl` MCP 调用官方 `@oai/sky`，依赖 Codex Desktop 提供的原生桌面控制通道。微信绑定不会自动创建另一套桌面控制服务；两个微信共享当前 Windows 用户的桌面。

## 故障与修复

2026-10-22 的失败记录包含 `Computer Use native pipe is unavailable` 和 `os error 2`。这是连接原生管道失败，不能解释为没有可操作窗口，更不代表用户查询的目标任务停止。

现场发现常驻 App Server 早于工具配置更新启动；新建同环境 App Server 可以读取窗口，指定失效管道则能复现原错误。证据支持旧进程保留失效工具配置这一原因，但未读取旧进程内存来确认其具体管道地址。

现在除了检查 Codex 可执行程序变化，还会对当前用户 `config.toml` 计算配置指纹。执行和观察连接在下一次相关请求前检查变化；空闲时重建 App Server，重新加载 MCP 配置并恢复会话。活动任务或控制查询期间不会为刷新配置而中断进程。指纹仅保存在内存，不记录配置内容、凭据或管道地址。

执行指令补充了桌面任务规范：先读取 Computer Use 技能，观察后操作，再回读结果；不能以更换模型、创建子会话或仅能枚举窗口作为操作成功的证明。读取控件只返回任务需要的信息，不输出 Cookie、密钥或凭据。

## 使用与边界

保持 Codex Desktop 和已登录的 Windows 桌面可用。锁屏、桌面控制组件退出、权限不匹配等仍可能使操作不可用；本次不宣称支持锁屏操作或所有高权限窗口。原生通道失效时应明确报告连接错误，不应伪造成功或绕过官方工具另建桌面控制实现。

配置刷新发生在请求边界，不会在正在执行的任务中透明重放界面操作。若故障发生在任务中，先确认哪些步骤已完成，再决定是否重试，避免重复执行。

当前用户反馈与统一验收范围见 [验收说明](acceptance.md)。本文保留本阶段具体工具验证边界；后续微信功能确认不代表所有应用和鼠标操作都已经验证。
