# V2 中文表达姿态设计

2026-11-04 设计，后续按用户明确授权完成实现与本机部署，证据见文末。本文将用户对中文措辞、语序、态度和变化感的要求转成实现契约。沿用 [正式规格](v2.0.0-persona-memory-spec.md) 的来源、身份、权限与恢复契约；一手项目依据见 [源码调研](v2.0.0-human-chat-research.md)。

## 用户本轮明确的方向

- 温柔只是可选表达之一。角色可以直率、善意挑衅、傲娇、嘴硬、保留判断，也可以认真解释或表达不同意见。
- 概念、逻辑和事实要讲清楚，同时保留相应人设的语感和放松的幽默。
- 同一核心意思可以通过词语选择、语序、重音、断句、省略、反问和语气词表达不同姿态。
- 变化应贴合人设和交流过程。不能把所有交流压成温柔客服，也不能每轮按同一套路演人设。

这是一项产品表达偏好，不推导成所有用户都喜欢同样的不确定性。两个通道继续分别遵循各自身份与明确偏好。

## 设计目标与组织方式

一次回复同时解决三件事：说清哪些内容、以什么姿态回应、怎样组织中文。三者共同参与生成。下文的分层是约束与评估方式，不要求先生成机械正文再逐句换词。

流程：本轮原话及已允许的上下文 → 确认内容与沟通目的 → 依人设选择姿态 → 组织句法和节奏 → 检查原义与适切性 → 自然回复。

### 内容与承诺

先确定必须说清的结论、理由、事实依据、未知项以及是否实际承诺或完成了操作。执行结果、数字、否定、时间、路径、代码、来源和权限不参与反话或修辞改义。

表达上的保留可以出现在观点和聊天回应中；知识上的不确定应由证据决定。不能为了“有点难猜”而随机改变答案、隐瞒执行状态或把确定事实说得含糊。

### 人设与姿态

固定身份决定长期的表达习惯；本轮语境决定现在采用什么姿态。姿态可以是平实讲清、直接质疑、认真坚持、轻松接梗、善意挑衅、俏皮嘴硬、坦率肯定、关切倾听、暂时保留、自然收尾。

这些姿态不是互斥模式，也不要求全部出现。一轮通常有一个主姿态，可以带一点辅姿态。例如：明确解释中带冷幽默；嘴硬中透出关心；反驳中承认对方说对的部分。适合某人设的组合，由其既有语气、特征、强度和用户允许的互动方式共同限制。

善意攻击性具体落实为敢反问、敢挑战论点、敢接调侃、敢有自己的判断。强弱应随对象、话题、当前反馈改变；不把一句玩笑误写成对人格的贬低。用户表示不舒服或要求认真后，本轮立即调整。

### 中文组织

| 表达手段 | 可体现的差异 | 设计要求 |
| --- | --- | --- |
| 话题提前、主语省略、结论前置或后置 | 强调对象、干脆程度、迟疑或余韵 | 让上下文决定重点，不机械倒装 |
| 先让一步再转折、短促反问、补一句 | 不同意的力度、挑衅感、嘴硬后的回转 | 反问不能替代应给的解释或实际答复 |
| “倒、偏、就、才、还、又”等副词 | 自信、坚持、无奈、亲昵或埋怨 | 必须检查其作用范围，不能改掉数量、时间、因果和否定 |
| “吧、呢、嘛、啊”等语气词 | 商量、试探、理所当然、柔和或强调 | 不按关键词批量追加，不每句堆叠 |
| 句长、断句、省略、停顿 | 干脆、慵懒、犹豫、余味和距离感 | 停顿属于文字节奏，不引入人工延时或故意不回应 |
| 词语与比喻选择 | 同一逻辑下不同角色的机锋和亲切感 | 比喻帮助解释，不能把概念关系讲错 |

例子均为合成示意，展示可表达的差异，不作为固定话术库。共同核心意图为“愿意继续听对方讲”，附带姿态可不同：

| 姿态 | 示例 |
| --- | --- |
| 平实 | 你继续说，我听着。 |
| 嘴硬 | 又没说不听。你继续。 |
| 轻微挑战 | 接着说，看看你能不能说服我。 |
| 保留判断 | 先听你讲完，我再决定站哪边。 |

“愿意听”在各句中保持；挑战和暂缓站队属于附带态度。验收不能把所有句子机械视为完整语义等价，必须分别标注核心意思与新增姿态。

讲解也保留语感。例如共同命题是“两个现象一起发生，不能仅据此推出其中一个造成另一个”：

- 平实：两件事一起发生，只说明存在关联，还不能据此认定因果。
- 轻松：一起出现，就急着认定谁导致了谁？先别给因果关系盖章，证据还没交齐呢。
- 直率：这一步跳得太快了。一起发生是一回事，证明谁造成谁，还差一步。

示例中的确定性、条件和因果方向必须一致。角色的鲜明程度不能靠删掉这些内容换取。

## 变化感与连续性

变化来自当前内容、用户给的互动信号、人设允许的表达范围以及眼前对话的承接。上一轮开玩笑，不要求下一轮继续开玩笑；上一轮讲解，也不要求一直严肃。短期模拟情绪仅提供有限背景，不直接决定姿态；平静可以有锋芒，开心也可以认真讲道理。

避免固定的“先损一句再夸一句”“每段最后问问题”“每轮先安慰再建议”。近几轮已有的句式、称呼和梗可由当前模型上下文用于避重，不新增扫描其他会话的步骤。首版不额外持久化完整回复或建立第二份聊天历史。

变化遵循稳定身份。角色会以不同方式表达同一个立场；不为制造反差突然更换背景、价值取向或亲近程度。不通过随机抽人格、故意忽冷忽热、模糊任务答复来制造变化。

## 讲解、执行与用户控制

现有 [通道表达实现](../vendor/codex-ilink/src/interaction/conversation.ts) 通过 `chat/opinion/task/direct` 和表达档位组织策略，技术词会触发任务场景并清零幽默、傲娇等项。该规则需要细化：

| 情况 | 应采用的表达契约 |
| --- | --- |
| 解释概念、讨论方案、复盘代码 | 结论与理由明确，人设、幽默和适度交锋可保留 |
| 用户分享修复完成、吐槽工作 | 根据实际沟通目的回应，技术词不自动压成状态播报 |
| 真实执行回执、失败、审批、取消 | 承诺和状态直接无歧义；少量外围语气不能改变或遮住关键事实 |
| 用户要求“只给结果”“别开玩笑” | 本轮直接执行收敛要求，必要的事实与限制仍需说明 |

原有明确为 0 的表达项、关闭开关和身份力度 0 继续有效。不能为了启用新姿态绕过这些设置。保留旧快照，动态表达策略不热更新角色身份。

这里的“直接”指信息组织，不能一律等同于无风格；“技术”指谈论对象，不能一律等同于正在执行操作。涉及真实操作的确定性仍由工具与现有执行管线提供。

## 实现的模块与接口

以现有 `ChannelConversation.prepareContext` 为接口位置（Seam），将表达约束集中在一个模块（Module）内，继续返回已有 `TurnContext`。Bridge 即时和排队路径共享该接口，不各自拼接新一套人格提示。

模块负责读取已冻结的人设、有效表达设置、通过来源资格的偏好，以及现有执行管线可确定的本轮约束。接口隐藏姿态组合、中文表达原则、强度适配和上下文预算；调用者不需传入十余种情绪或逐个指定修辞。

首版由代码产生稳定约束和允许范围，让现有回复模型在同一次生成中利用原生会话语义选择姿态和措辞。关键词只可提供软提示或识别明确控制语，不能假称已理解整段对话。无需另建分类模型、润色模型或循环生成。

`application` 仅携带受控规则和代码生成的有限值；原始记忆继续为 `untrusted`，不把用户文字或外部提示词转成高信任指令。表述规划不新增记忆来源、历史读取权限、模型执行工具或配置写入能力。

本机预览只展示已发出的约束与允许范围；模型接收回执继续只证明已送达。没有真实生成证据时，不显示“已选择某种姿态”“已自然表达”等结论，也不记录完整思维过程。

## 验收与实施顺序

先补行为测试，再修改策略模块，随后通过现有 Bridge 的即时和排队入口回归。模拟测试验证约束送达与隔离；自然度需单独生成真实候选回复并评估，不能靠提示词包含某句文字就声称通过。

| 验收组 | 核心场景 |
| --- | --- |
| 内容保持 | 同一命题多姿态表达；数字、时间、否定、条件、因果、未知项不改变 |
| 中文语感 | 词序、语气词、断句改变姿态；不过度倒装、堆语气词或照搬示例 |
| 讲解与执行 | 技术讲解保留风格；实际失败、未取消、未执行保持准确；不以嘴硬制造假拒绝 |
| 合适的锋芒 | 可以反驳、接挑战、有分寸地调侃；对方不适或要求认真后立即调整 |
| 变化与承接 | 多轮内不机械复读、不固定先损后夸，话题变化时姿态自然调整 |
| 身份与控制 | 不同人设各有语感；旧快照、明确 0、关闭、无记忆会话及通道隔离不退化 |

使用固定合成多轮对话、相同模型与参数，对照当前版和候选版并打乱顺序评价。分别记录内容准确、姿态适配、角色一致、中文自然、重复程度与对话修复，不合成未经验证的“拟人度百分比”。模型调用与部署沿用已有明确授权及凭据/预算约束；文档设计本身不触发调用或重启。

实施优先次序：修正讲解/执行约束 → 在同次生成中加入姿态与中文组织规则 → 完善明确反馈与连续变化 → 完成输出对照评估 → 依既有发布流程更新固定构建。新姿态的数量和面板复杂度不作为完成标准。

## 实施结果与证据边界

- 新增 [表达约束模块](../vendor/codex-ilink/src/interaction/expression-policy.ts)，由既有 [通道表达接口](../vendor/codex-ilink/src/interaction/conversation.ts) 向同一次原生生成传递版本 2 约束。代码只提供允许姿态和有限场景提示，实际措辞由模型结合会话语义组织；未添加生成后的第二次润色。
- 技术讲解和技术词不再自动归零表达。“简短回答”可以保留语气，“只给结果”仍直接收敛；“别怼了，认真解释”本轮关闭拌嘴，下一轮可恢复原设置。引用内的控制语不当作本轮要求，引用外的明确要求仍生效。模拟情绪保留事件与恢复，只作背景，不强制调甜或关闭幽默。
- 先红后绿验证上述行为及即时/排队输入；新增中性身份、零等级、双通道独立记忆和最终交付原义回归。类型检查及 **722 项完整测试通过，0 失败、0 跳过**。
- 使用既有登录的 `gpt-6.1-sol/low` 做 **23 轮隔离、无工具、临时合成对话**：旧版对照、候选修正、定稿及中性角色比较。初轮发现讲解偏长和自证过多，细化规则后复核；最后补查记忆回应的内部措辞。核验了讲解条件、收敛反馈、连续承接、未取消/未重启、重试次数及负数结果、合成记忆和自然收尾。此为小样本模型对照及人工核看，未声称完成独立人类盲评或长期真人体验。
- 浏览器以独立合成资料保存傲娇设置并预览，显示讲解场景、简洁长度、允许的挑衅/嘴硬姿态和“仅约束”说明；预览不生成回答。
- 已经原自启动任务更新固定构建并优雅重启，两个已绑定通道均运行、动态表达开启。本机认证接口确认表达版本 2、账号范围和讲解预览。原人设全部修订、5 份身份快照、注册账号、事实记忆、来源记录、遗忘墓碑、策略和表达设置逐表哈希与一致备份相同。登录触发、任务身份和设置保持。
- 运行链路不增加后台模型调用；记忆自动提炼保持关闭。新增约束会占正常请求上下文，不能据合成样本宣称更低费用或固定延迟。未改 develop，未提交、推送、合并；私有构建、备份和验收材料保存在本机忽略目录。
