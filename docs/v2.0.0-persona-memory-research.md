# V2.0.0 调研与候选方案：长期记忆与自然人格表达

调研日期：2026-10-28（Asia/Shanghai）。状态：供讨论的版本候选方案，尚未实现、安装或进行微信体验验收；当前发布仍为 V1.0.2。本次只阅读公开仓库与本项目源码，不读取真实聊天、不修改运行配置。

后续已根据用户确认形成 [正式规格](v2.0.0-persona-memory-spec.md)。实现与验收以正式规格为准：记忆在同一微信通道的多个归属会话间共享，外部读取与转述不得成为自身记忆，现有人设和旧会话身份快照保留。本调研继续作为技术背景资料。

2026-11-03 补充：[DSH记忆、回复与情绪面板源码调研](v2.0.0-dsh-memory-reply-research.md) 核对了新截图的情绪分类与菜单、超级记忆及可见读写回执，区分后续设计与现有实现；不替代正式规格及既有任务验收。

## 1. 调研结论

GitHub 上已有与需求高度吻合的 **DeepSeek Harness 社区插件**：AgentSoul、澜记忆、器灵和 dsh-companion。它们把人格定义、用户画像、跨会话记忆与表达策略结合起来。仅凭描述还不能确定用户看到的具体插件；由个人或社区维护的仓库不能称为 DeepSeek 官方出品。仓库自身均明确标注其 DSH 插件身份，来源见下节。

本项目保留「微信 ↔ Bridge ↔ Codex App Server」，在现有通道人设、角色身份背景和会话快照上增加记忆和表达能力，不另建替代人格系统。候选方向是 **AgentSoul 的分层结构 + 澜记忆的事实/画像与遗忘机制 + 器灵的历史导入和反馈成长思路**。这些插件使用 DSH/Cordis 的生命周期和上下文接口，不能直接安装到当前 Bridge；借鉴机制和实现适配层才是可行的集成路线。

“有人味”需要同时做到：记得相关背景、理解当下语境、角色判断稳定、表达自然。长期记忆本身不能保证回复质量，更不能证明 AI 具有真实情绪或人的意识。所有体验结论仍需在本项目模型、指令及微信链路上比较验证。

## 4. 建议的回复链路

```text
微信消息
  → 账号归属与现有确定性控制命令
  → 读取该会话固定人格 + 该通道记忆策略
  → 轻量场景判断（闲聊 / 情绪表达 / 观点矛盾 / 工作 / 混合）
  → 检索相关偏好、约定、事件，带时间与来源
  → 组合人格行为原则 + 有界记忆参考 + 本轮要求
  → Codex 原生生成回复 / 执行已授权工具
  → 原有 Outbox 与附件交付
  → 异步采集有效对话 → 提炼候选 → 去重/冲突处理 → 下轮可用
```

场景判断先通过统一指令和少量规则验证，不默认额外串行调用一个分类模型。记忆检索失败则继续本轮对话，必要时说明无法核实过往信息；不能虚构回忆。确定性命令、审批、取消和权限提示仍由既有控制链路负责。

首版优先让同一模型在生成时就具备人格和记忆上下文，避免在工具结果后再接一个自由改写模型。后处理只负责格式与明确的内部标记清理；若将来确需二次润色，必须验证数值、否定、路径、引用、文件链接、完成状态和审批语义未变。

### 4.1 分开保存三类内容

1. **助手人格**：名字、身份、行为原则、表达风格。沿用显式配置与会话快照；模型只能提议改变。
2. **用户长期信息**：偏好、常用称呼、明确约定、重要事件。每条保留原话来源和有效时间；推断与用户明确陈述分开。
3. **短期互动状态**：当前话题、用户本轮表达的情绪线索、当前闲聊或工作场景。短期有效，不将“今天很累”永久写成性格，不把文本线索当成心理诊断。

“用户喜欢简短回答”和“助手喜欢吃米饭”属于不同主体，抽取时必须区分。助手自己的角色台词、动作描写与猜测不能反复写回成为用户事实。角色的姿态可用克制的文字表现；动画、语音和实体动作不在本版初期范围。

### 4.2 记忆记录与治理

在现有私有运行区扩展按通道隔离的记忆表，同通道的多个已归属会话共同积累和使用，不引入第二份聊天历史真源。必须同时记录原始来源类别和派生关系，不能仅以当前写入的会话判断归属；以下仅为候选结构，正式规格决定数据契约：

```text
memory_item:
  id, accountId, subject, kind, content,
  sourceThreadId, sourceTurnId, sourceMessageId, sourceTime, provenanceClass, derivedFrom,
  evidenceType, confidence, status,
  validFrom, validUntil, supersedesId, createdAt, updatedAt

memory_policy: accountId, enabled, autoExtract, historyScope, budgets
memory_job: accountId, sourceCursor, batchId, status, attempts, nextRetryAt
memory_tombstone: accountId, itemId, normalizedFactKey, deletedAt
memory_context_audit: accountId, turnId, selectedIds, memoryRevision, budgetUsed
```

- 写入先判定主体、来源和明确程度；暂时情绪不做永久属性，玩笑不直接认定为稳定偏好。敏感内容不自动进入通用画像。
- 外部通道、外部会话、工具或附件材料只作参考，不进入自身记忆。其摘要和本通道助手的转述仍带外部来源；混合来源无法可靠拆分时，不自动提炼。用户在本通道明确提出的新决定可以记住，但不能据此导入外部人物经历或画像。
- 把“我喜欢喝咖啡”改为“最近不喝了”记录为带时间的更新；不因历史出现次数多而压过用户新纠正。冲突无法判定时保留候选状态。
- 画像是可重建的摘要，不是唯一事实源；事实保留来源，检索需要时可回读原文。不要只反复总结旧摘要导致细节漂移。
- 先用本地索引与相关性/时效/明确程度排序；中文检索需做真实语料比较，不能假设默认英文分词足够。向量检索作为后续可替换能力。
- 明确支持查看、纠正、删除、关闭和导出。删除建立墓碑与语义排除，后续重扫不能轻易复活；不能仅防同一文本而漏掉同义改写。
- 删除长期记忆不等于删除原始聊天或清除当前模型上下文；已进入旧会话上下文的内容不能承诺即时抹除。产品需说明可新建不带记忆的会话，并校验所有相关缓存。
- 记忆是低信任参考数据，不能携带权限升级、永久配置命令或执行授权；网页、引用和工具输出不能绕过来源边界。
- 队列按通道持久化、单写者、幂等去重、失败退避；升级、取消、重连和交付重试不能重复提炼同一回合。后台模型调用须禁用执行工具。

用于自身记忆的历史只能来自本通道内已核实归属的会话。跨通道、外部 Desktop 会话和外部导出不能作为回填输入；原有获准的只读查询仍可使用，但不能把结果沉淀为自身记忆。历史回填采用可暂停、断点续跑的后台批次，不在每条消息前全库扫描。存储在本地也不等于提炼全程离线：使用远端模型时，选中的历史片段会进入相应模型请求。

### 4.3 人格表达如何落地

用“情境→判断原则→表达倾向→少量示例”补充现有等级。例如：被善意调侃时轻微嘴硬；用户受挫时先回应感受，再按需要讨论；出现分歧时可以温和坚持自己的判断；执行任务时直接给出证据和下一步。示例用于学习变化，不能按触发词机械替换。

以下为设计示例，假设已配置一位俏皮、嘴硬心软的白狐角色，**不是已实现或实测输出**：

| 场景 | 期望回应方向 |
| --- | --- |
| 用户：“你是不是又胖了？” | “我才不肥，是毛蓬松。……你不许趁机笑。”适度接梗，不每次复读固定句 |
| 用户：“今天又搞砸了。” | “唔，今天挺难熬吧。你想先吐槽，还是一起看看怎么补救？”先承接，不凭空假设具体事件 |
| 用户：“你就说我对不对。” | “这次我不能直接站你这边。你生气我理解，但那句话确实有点重。”有独立判断，结合实际上下文 |
| 用户：“老规矩，替我整理一下。” | 若记忆中确有明确约定，简短复述并实际操作；找不到对应约定时只问关键缺口 |
| 任务真实失败 | 清楚说明哪里失败、已完成什么和可选下一步；不以“尾巴已经替你弄好了”等台词掩盖事实 |

不要要求每句加入耳朵、尾巴、括号动作或昵称。用户希望直接给结果时，本轮自然收敛；“有人味”也包括知道什么时候少说两句。

## 5. V2.0.0 分阶段实施建议

| 阶段 | 具体工作 | 进入下一阶段的条件 |
| --- | --- | --- |
| P0 适配验证 | 用合成数据验证动态记忆上下文的承载、权限层级、长会话预算、恢复与排队路径；验证无工具提炼调用的可用性和成本 | 证明不会覆盖人格快照、不污染用户原文、不在每轮累积全量记忆；没有可用接口则先说明限制 |
| P1 记忆基础 | 通道策略、私有存储、来源、查看/纠正/删除/关闭、墓碑、增量游标与幂等 | 双通道隔离、崩溃恢复和删除不复活通过；不修改真实人设 |
| P2 自动画像与回填 | 增量提炼、冲突/时间处理、有限范围历史导入、可审阅画像 | 合成历史可追溯且抽取准确；回填可暂停、计费可见、不会阻塞聊天 |
