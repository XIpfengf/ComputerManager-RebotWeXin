# V2 分支功能与试点操作说明

当前发布标签为 V1.0.2。本页描述 V2 分支功能。正式边界见 [规格](v2.0.0-persona-memory-spec.md)，本机部署与验证范围见 [验收说明](acceptance.md)。

## 范围与默认值

部署层默认关闭整个 V2 扩展。只有部署者在私有环境变量 `ILINK_V2_ACCOUNTS` 中列入的已认证账号别名，才启用新版表达编译器与记忆控制入口；逗号分隔，不支持显示名、通配符或自然语言选择。未列入的通道继续使用基线表达编译器。设置部署范围不等于开启记忆，记忆与自动提炼仍各自默认关闭。更换试点仅改变功能范围，不复制不同通道的记忆事实、来源或身份；原通道移出范围后停止扩展注入与后台，存量数据保留。

已有角色资料和旧会话身份指令保持原快照。新版指导只编译进未来新会话；无记忆临时会话也沿用现有新建权限与身份规则。记忆属于通道，不能改变角色背景、模型默认值或权限。

显式与自动记忆仅接受来源可证明的用户本人陈述。首版保守处理不超过300字的稳定偏好、决定或事件表达，例如“我偏好简短回答”；不会给全部闲聊建立自动画像。引用、附件、工具结果、助手复述、来源未知的旧历史和可识别的凭据不会成为用户事实。

## 控制语法

以下均须由该通道控制者直接发送纯文字；语音、引用、附件和模型路由不能修改永久策略。

| 命令 | 行为 |
| --- | --- |
| `memory help` / `memory status` | 帮助和当前开关 |
| `memory enable` / `memory disable` | 开启或关闭采集、后台和注入；已有事实保留 |
| `memory remember 我喜欢米饭` | 显式记录本人陈述与来源 |
| `memory show` / `memory source <ID>` | 最近100条有效/冲突事实，或指定条目的原话、修订和状态 |
| `memory profile` | 从有效证据重建最多100条的有界用户投影，冲突单独显示 |
| `memory candidates` | 查看不参与注入的待确认候选 |
| `memory correct <ID> <修订> <本人新陈述>` | 明确纠正或确认候选；保留被取代证据，拒绝过期修订 |
| `memory forget <ID> <修订>` | 遗忘事实和派生，保留排除记录；不删除原始聊天 |
| `memory export [游标]` | 每页最多100条本通道有效/冲突事实；有下一页时返回游标 |
| `memory private` | 新建不读取、不记录的临时会话；其历史永久排除回填 |
| `new` / `exit` | 新建普通会话 / 返回原主会话，保持已有语义和忙碌保护 |
| `memory auto enable/disable/status` | 单独控制后台提炼并查看计数和预算 |
| `memory auto reconcile/cancel` | 本地核对未知结果 / 取消未确认提炼；不盲目重发 |
| `memory backfill preview [会话ID]` | 预览本通道可核实范围和有限预算，不读取原始历史 |
| `memory backfill start <确认码>` | 两分钟内明确确认该预览范围 |
| `memory backfill status/pause/resume/cancel` | 查看分页进度，暂停、续跑或取消；complete仅指遍历完成 |

关闭期间收到的消息，执行或重新开启时仍不读写记忆，也不能以后补采。关闭和遗忘无法抹除已经进入旧模型上下文的片段；需要新的上下文时使用无记忆新会话。

遗忘排除按原始证据、规范键和保守主题族共同判断；同义或无法证明独立的自动候选会被跳过，可能少记部分新事实。重新记录须有新的明确操作，不解除旧证据排除。归属变化一经观察会持久隔离来源，单纯改回归属标签不能自动恢复。

## 提炼后端与预算

用户已批准采用独立无工具 Responses HTTP 适配器，不建立另一个执行器。私有配置键为 `ILINK_MEMORY_RESPONSES_MODEL`、`ILINK_MEMORY_RESPONSES_API_KEY`，可选 `ILINK_MEMORY_RESPONSES_ENDPOINT` 为完整 HTTPS Responses 地址。没有内置模型默认值，不读取或复用 Codex 登录凭据。模型、凭据、端点与费用须在真实试点前核实，密钥不贴聊天、不写进仓库。

请求关闭工具并使用结构化输出，客户端没有工具执行分发；只发送该通道通过来源校验的必要原话。工具控制与结构化结果字段依据 [OpenAI 工具文档](https://developers.openai.com/api/docs/guides/tools) 和 [结构化输出文档](https://developers.openai.com/api/docs/guides/structured-outputs)，不保证任意兼容端点都支持，须实测。

每次最多一条逐字事实，输入/输出各限4096字节，HTTP完整响应限64KiB，输出上限1024 token，默认超时10秒。每账号每UTC日最多50次提炼尝试；已知失败最多3次，60秒起指数退避。未知调用结果暂停，不因重启重复计费；没有可取回的提供方结果就保持未知。

`memory auto status` 的日调用预算跨重启保留；提供方 token 和最近100次调用延迟仅统计当前进程已收到的响应。缺失用量不按零处理，不能据此估算完整账单。[提供方用量字段](https://developers.openai.com/api/reference/cli/resources/responses/methods/create) 与本地调用预算是两个口径。

## 检索、回填与故障

动态事实使用原生 `additionalContext` 的 `untrusted` 类型，用户原文、附件和身份指令保持独立。固定来源键每轮重新构建，内容最多4096 UTF-8字节。实际宿主的替换/清空、持久化和低信任语义仍须最后试点核实，schema或替身通过不能代替原生运行证据。

本地检索先按主题和文字筛选，再在预算内选择，支持有限中文同义映射；没有向量库，也不声称任意语义都能召回。候选不注入，冲突保留状态，读取故障与零命中区分。完整审阅使用分页导出，分页期间发生修改应重新导出。

回填仅处理已核实归属且有原始来源记录、回合关联和匹配原文哈希的历史；未知旧历史明确跳过。每次确认最多20个会话，每会话10页、每页10回合；超限标记limited，显式续跑才增加预算。暂停阻止后续回填调用，已发出的模型调用可完成。归档不转移归属，回填不能导入其他用户、外部导出或角色迁移材料。

损坏的事实或待提炼正文会被校验拒绝；扩展初始化失败时普通任务仍能提交，并标明记忆不可用。底层路由与记忆共享SQLite，整个原路由数据库或磁盘损坏不属于“仅记忆扩展故障”，不能承诺原服务仍可运行。

## 验证与试点

离线回归、合成体验及试点验证的范围见 [验收说明](acceptance.md) 和 [表达验证](v2.0.0-expression-design.md)。逐项工单、真实通道映射、受控备份、凭据和原始试点日志只在本机维护。

部署沿用本机操作授权。真实自动提炼试点还须核实指定通道、操作窗口、模型及费用。部署复用现有 Bridge，微信实机验收与模拟验收分别记录。


## 试点自启动与版本一致性

试点的当次运行和登录自启动应使用同一份已验证构建。仅临时从工作区启动、保留原主目录自启动入口，会在后续服务启动时回到旧代码；进程running不能证明新功能仍在运行。

内部启动入口为构建中的 `dist/cli/pilot-startup.js <本机私有配置文件>`。配置记录固定构建目录、已核验状态库位置、唯一账号别名和注册身份指纹，当前只允许显式记忆模式。启动前逐文件核验构建清单并只读核对账号；异常时明确失败，不自动回退到另一个源码目录。模型与密钥不写进任务参数，自动提炼配置仍需另外落实。

部署快照应包含dist、插件资源、包元数据与MIT许可；日志、配置、启动回执、任务XML和数据备份留在忽略的私有位置。更新自启动只更换任务Action，保留原登录触发、执行身份、隐藏运行及重试设置。原任务与数据备份在切换前保存；回退优先恢复运行入口，不在线覆盖SQLite或删除试点记忆。

验收须实际通过计划任务启动、停止后再次启动，核对新PID仍为同一构建和同一账号范围，并复验真实只读项目查询与旧身份快照。该验证不等于已实际注销/登录或整机重启，也不代替微信端到端体验。工作区后续修改不会热更新固定快照；重新部署须再验收并更换构建。试点期间不要运行原主目录的重新注册命令覆盖此任务。


## 委派管理与全通道范围

当前部署支持将多个已核验账号写入私有启动配置accounts列表，逐一验证注册身份，生成明确的ILINK_V2_ACCOUNTS清单；开放功能不等于跨通道共享历史、记忆或桌面授权。现有会话身份快照保持，新版表达用于未来新会话。

delegate_task支持retry推进既有委派及cancel取消排队任务。唯一且刚核验的目标可承接当前会话的明确委派；真实歧义仍应选择。催办不重复发送未知结果，取消不把已投递目标冒充已停止。后台小页核对并显示具体阻塞、错误与最近核对时间。升级中存在用户手工交接/取消争议的历史排队可暂缓；用户自然语言催办或取消后处理，不能盲目回放。


## 从微信创建项目Desktop任务

用户明确要求新建时，delegate_task的create动作支持project、完整instruction、可选model/effort/title。只从Desktop真实项目列表选择已保存本机项目，不创建云任务、worktree或内部子代理替代。项目歧义需选择；模型及推理强度必须在用户本轮明确指定且可核验，未指定时保留项目/应用默认值。

新会话通过Desktop官方create_thread接收初始任务，返回真实threadId后按认证账号登记归属，接入原委派结果回传链路；不会再submit一次。当前微信绑定及身份不变，新项目会话遵守项目既有规则和审批。instruction必须带入用户批准的完整方案与限制，不能只写“按之前方案”；本轮上传附件可作为资料传入，模型不能指定额外本机文件路径。

creation_status查看当前来源会话的新建回执。新建请求在副作用前持久化，同轮重复调用不会重复创建；超时、pending client ID或本地登记失败会保留未知/待核实状态及可用回执，禁止自动重建或冒充任务完成。新建请求与结果按通道隔离，不将任务资料写入另一通道记忆。

旧会话的动态delegate_task schema可能被冻结。当前新能力使用MCP服务器ilink_delegation中的ilink_delegate_task入口，旧名仅保留兼容；不能因旧schema没有create就判断服务不支持。新建请求会核对当前线程实际工具清单，发现失败时明确提示未加载。部署验收需同时检查旧会话工具清单与模型可见性，不能仅检查进程和后端模块。

工具路由说明每轮通过application上下文刷新，避免已加载旧会话沿用过期“不支持创建”的判断；这不会改写人设快照或把通道记忆提升成指令。中文模型选项可写“GPT‑6.1 Sol／高”，“高质量方案”本身不表示选择高推理强度。

## 2026-11-03 表达与情绪扩展

用户已批准实现动态表达、独立情绪、本地召回与来源回执，并在验收后更新自启动，为两个已绑定通道启用。命令、控制页、上下文信任层级与关闭方式见 [动态表达与本机控制页](v2.0.0-interaction-guide.md)。仍保留既有人设、旧身份快照、严格记忆来源；自动HTTP提炼不因本增量自动开启，未配置额外模型或凭据。
