## 修改时的同步顺序

1. 先核对源码、测试和真实反馈。区分自动化、隔离实机、实际微信及尚未验证。
2. 更新所属功能专题的契约或限制；命令变化同步使用手册，数据位置变化同步目录结构。
3. 在验收说明更新当前结论及仍未覆盖项；专题阶段记录标明时间，不把旧测试数量当作最新结果。
4. README 只更新能力摘要与入口。新增、删除或改名公开文档时维护相对链接。
5. 提交前检查实际暂存文件及内容，排除环境密钥、真实配置、数据库、私有消息、机器路径与原始日志。通用忽略放 `.gitignore`，机器专属规则放 `.git/info/exclude`，本机证据放 `.local/`；保留原始数据，不强制纳入索引。

忽略规则不能处理已跟踪的敏感文件，也不等同于权限控制。若出现已跟踪私有文件，先保留本机副本，再解除跟踪并替换公开引用；若凭据曾泄露，另行处理凭据失效，不通过改文档声称消除历史泄露。
