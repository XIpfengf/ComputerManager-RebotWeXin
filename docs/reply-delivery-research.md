# 长回复完整交付与长任务提示研究

日期：2026-10-17。只研究及使用合成文本只读复现；不修改代码、运行配置，不发送微信测试消息，不重启服务。

## 结论一：长回复可修复，当前是本地主动截断

[wechat-output.ts](../vendor/codex-ilink/src/bridge/wechat-output.ts) 设置最多 3 条文字，每条最多 2,000 UTF-8 字节；剩余正文被丢弃，并加上用户截图中的“内容已截断”提示。中文通常每字 3 字节，因此不能把 2,000 字节理解成 2,000 个汉字。

[Bridge 最终交付](../vendor/codex-ilink/src/bridge/bridge.ts) 采用 `maxMessages: 3 - mediaBodies.length`，附件还占用这 3 条总配额；1 个附件只剩 2 条文字，2 个附件只剩 1 条。Desktop 通知也使用同一个格式化器。

只读复现：3,000 个合成汉字加末尾标记，共 9,024 UTF-8 字节。分别按 3/2/1 条配额格式化，末尾标记都消失，末条均出现截断提示。无需真实账号、网络或模型即可确定这一损失发生在本机格式化阶段，不能因此断言所有长消息问题都来自这一处。

腾讯官方适配器目前声明 `textChunkLimit: 4000`，但这是 OpenClaw 适配器配置，未明确为服务端 UTF-8 字节硬限制。官方单条发送器直接构造 TEXT item；不能据此保证任意长度或不限条数连续发送必定成功。[官方适配器](https://github.com/Tencent/openclaw-weixin/blob/main/src/channel.ts)、[官方发送实现](https://github.com/Tencent/openclaw-weixin/blob/main/src/messaging/send.ts)、[协议说明](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol_zh_CN.md)

推荐修复策略：

1. 普通长度保持一条；较长正文按段落、句子分片，并增加分片编号，保留 Unicode 字符边界。
2. 先保留保守的单条字节预算，不通过盲目放大单条长度修复；编号也计算在预算内。附件数量和正文分片预算分开设计。
3. 特别长的回复采用短导读加完整原文 txt/md 附件，或提供按持久化游标“继续”的方式；全文来自已完成回合，不重新请求模型生成后半段。建议先实现自动全文附件，避免几十条刷屏。
4. 自动全文附件必须走任务/账号范围内的受信任生成与暂存链路，不依赖模型自行调用 send_file，也不放宽任意路径外发。与用户原有附件的配额冲突要明确处理，不能又悄悄丢正文或附件。
5. Outbox 保存完整交付计划与分片序号，失败重试保持相同身份、顺序和账号。不能只将常量 3 改大：`#finalReplyOutbox` 固定读取前三片，[SQLite 清理逻辑](../vendor/codex-ilink/src/bridge/sqlite-state.ts) 也枚举前三片，恢复/完成判断需一起改。

此方案修复的是完整性。文件交付失败或正文特别大时应明确报告未完成的交付，并保留可恢复内容；不承诺网络失败时一定送达。

## 结论二：长任务提醒可优化，当前不是卡死判断

[Bridge](../vendor/codex-ilink/src/bridge/bridge.ts) 默认阈值 `2 * 60 * 1000`。`#notifySlowDispatch` 检查 accepted、未完成、turn 身份相符，并比较当前时间与 dispatch.updatedAtMs；消息在后续轮询对账时发出，不保证正好两分钟。

updatedAtMs 主要记录提交状态变化，不是每个工具进度的最后活动时间，所以有正常进展的任务也可能触发。提醒使用固定 `codex-ilink:<turn>:slow` 身份，通过 Outbox 去重/重试，旨在提醒“仍未完成”，不会取消任务。原文中的“可能正在等待工具、审批或网络”是泛化推测，不是状态检测结果。

推荐分两阶段优化：

- 先修改措辞：例如“任务还在处理中，已用时约 2 分钟。完成后会自动发给你；可发 st 查看，或发 stop 停止。”不暗示故障，也不承诺没有证据的具体进度。
- 后续基于真实执行事件记录最近活动、工具阶段和实际待审批状态；优先提示“正在扫描目录”“等待你确认”等可证实状态。只有较久无新活动时才给通用等待提醒；没有证据就只显示已用时。
- 提醒按回合和账号隔离、限频；临近完成不新增提醒，终态后废弃尚未投递的旧进度，避免先收到结果又收到“仍在执行”。
- 保留输入状态提示及 st/stop 作为补充；不直接转发原始命令、文件路径、推理内容或高频 token 流，不用虚构百分比表现进度。

优先级建议：先修复内容完整性；长任务提示先做文案优化，再扩展真实进度状态。本文不视为实现授权或实机验收通过。
