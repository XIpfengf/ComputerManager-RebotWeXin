### 2.1 情绪如何真正影响表达

JMX 的实现并非只有调节条：[配置](https://github.com/JMX-4869/dsh-mood/blob/aed059a787c6f94b1d7c3c04f71ffd78dea60990/index.js#L506) 定义切换余量、保持时间和混合窗口；[恢复与混合计算](https://github.com/JMX-4869/dsh-mood/blob/aed059a787c6f94b1d7c3c04f71ffd78dea60990/index.js#L857) 形成状态；[提示词注入](https://github.com/JMX-4869/dsh-mood/blob/aed059a787c6f94b1d7c3c04f71ffd78dea60990/index.js#L1802) 把主导/混合状态映射成表达倾向。

其 [PERSONA_PRIORITY](https://github.com/JMX-4869/dsh-mood/blob/aed059a787c6f94b1d7c3c04f71ffd78dea60990/index.js#L800) 明确身份、长期偏好和短期心情的关系。但 README 同时说明“心情不进入长期记忆”有赖提示词约束，不能当作存储层硬隔离已成立。本项目应让情绪事件与事实记忆走不同写入接口，不能仅增加一段提醒。

“鱼的心情”核对提交 [`1881cef1ae348a991c634647e8a0561d7452f9fd`](https://github.com/Yuuyuko-uu/dsh-feiyu-mood/commit/1881cef1ae348a991c634647e8a0561d7452f9fd)。其 [配置与状态](https://github.com/Yuuyuko-uu/dsh-feiyu-mood/blob/1881cef1ae348a991c634647e8a0561d7452f9fd/lib/index.js#L151) 和 [注入闸门](https://github.com/Yuuyuko-uu/dsh-feiyu-mood/blob/1881cef1ae348a991c634647e8a0561d7452f9fd/lib/index.js#L1533) 实际包含置信、显著变化、每日次数及去重控制。当前源码的恢复默认值与 README 的部分旧说明不同，应以固定版本代码为核验依据，不照抄网页数字。

### 2.2 “超级记忆”的权重并不等于记得更多

核对 [kkwings/dsh-super-memory](https://github.com/kkwings/dsh-super-memory) 提交 [`b10764487b5923ea55dc704c26f3701d4535bf0a`](https://github.com/kkwings/dsh-super-memory/commit/b10764487b5923ea55dc704c26f3701d4535bf0a)。[命中门与打分](https://github.com/kkwings/dsh-super-memory/blob/b10764487b5923ea55dc704c26f3701d4535bf0a/lib/retrieval.js#L79) 先检查证据，再计算排序；[时间重排](https://github.com/kkwings/dsh-super-memory/blob/b10764487b5923ea55dc704c26f3701d4535bf0a/lib/retrieval.js#L557) 保留原始词法分，不借时间权重放宽资格。[配置](https://github.com/kkwings/dsh-super-memory/blob/b10764487b5923ea55dc704c26f3701d4535bf0a/lib/config.js#L29) 区分检索门槛、单轮条数和文本预算。

值得采用的是“最早/上次/最近”对应不同的时间需求，以及无强相关内容时允许不注入。具体分数是检索器内部尺度，不是可靠性概率。其默认可保存读类工具资料，目标是恢复长会话上下文；本项目的自身记忆来源更窄，不能直接使用这套采集范围。

### 2.3 让用户看见记忆读写

核对 [omdsh-dev/dsh-mnemon](https://github.com/omdsh-dev/dsh-mnemon) 提交 `54cca5fc2e552483ae13e68565564149fd03a1df`。[回合范围](https://github.com/omdsh-dev/dsh-mnemon/blob/54cca5fc2e552483ae13e68565564149fd03a1df/src/core/turns.ts#L84) 绑定当前存储及会话；[写回执](https://github.com/omdsh-dev/dsh-mnemon/blob/54cca5fc2e552483ae13e68565564149fd03a1df/plugins/dsh-mnemon-source-runtime/src/source.ts#L95) 核对 revision；[评分策略](https://github.com/omdsh-dev/dsh-mnemon/blob/54cca5fc2e552483ae13e68565564149fd03a1df/plugins/dsh-mnemon-source-memory-spaces/src/recall-quality/policies.ts#L20) 区分不同分数语义。这些比单独展示“记忆强度 100”更能帮助排查忘记、错记和误召回。

对照发现还包括：dsh-living-memory 有候选不足回退全库的分支（[代码](https://github.com/dearbld/dsh-living-memory/blob/1d8d43c708ad8ed80f9faebdcf22001e99845b8d/index.cjs#L11887)）；WaveMemory 的心情按 Bot 聚合多个会话事件（[代码](https://github.com/vivy1024/astrbot_plugin_wave_memory/blob/2f8eae61bcd807b44630102c87edc25f36dbeb79/services/bot_mood.py#L490)）。这不等于其产品有缺陷，但与本项目严格通道隔离不同；候选不足和面板切换账号都不能扩大本项目的数据范围。

## 3. 当前代码与目标之间的差距

| 层 | 当前分支源码 | 需要增加的能力 |
| --- | --- | --- |
| 稳定身份 | [Profile 与编译器](../vendor/codex-ilink/src/profiles/profile.ts)、[通道快照](../vendor/codex-ilink/src/profiles/channel-profile.ts) | 保留旧快照，不由情绪或自动反思改写 |
| 回复风格 | 温暖、傲娇、幽默、表情 0–5，长度档位，工作场景收敛 | 可查看的每轮风格选择、场景偏好、频率与重复控制 |
| 长期记忆 | [通道服务](../vendor/codex-ilink/src/memory/channel-memory.ts)、[中文主题匹配](../vendor/codex-ilink/src/memory/semantics.ts)，已有来源与纠错/遗忘 | 更好的中文召回、时间意图、可解释排序与选择记录 |
| 短期情绪 | 没有独立的可持久化情绪状态机 | 账号内事件、恢复、防抖、限频及表达映射 |
| 可视配置 | 微信配置/记忆命令 | 共用同一后端的本机控制页、来源查看和回复预览 |

## 4. 建议的落地设计

这是基于源码的设计推论，尚未写入正式规格或启用运行功能。

### 4.1 三种数值分别管理

- **回复风格偏好**：甜度/幽默/傲娇/主动追问/表情/长度。区分用户设定、当前生效值、场景调整与调整理由。现有等级只有 0–5，若面板用 0–100 展示，必须说明映射和有效精度；不能暗示已有 101 档行为。
- **情绪状态值**：按账号保存，展示主导和混合状态、最近事件与恢复情况。它不是用户人格档案，也不是模型内部权重。自动判断不确定时不写成事实，不复制其他账号的情绪原因或状态。
- **记忆检索参数**：相关性、时间适用性、明确纠正、用户固定项、重复与预算分别可解释。来源合规及删除/失效状态是不可被权重覆盖的资格条件。

流程：认证账号与原始来源过滤 → 有效性/纠正链核对 → 中文召回 → 时间与偏好排序 → 去重和预算 → 注入低信任记忆 → 保存本轮选择回执。没有合格记忆就不注入，绝不回退到其他通道。

### 4.2 先让已有表达偏好真正生效

用户要求“问你怎么看时甜一点、幽默一点”，应作为明确表达偏好保存并在意见交流场景应用，不必先推断“心动 90”。“直接给结果”、失败、取消与审批场景应收敛表达。语气不能修改否定、数字、代码、路径、执行状态和来源。

推荐的回复诊断视图展示：当前身份版本、采用的风格档位、命中的偏好/记忆及原始来源、被排除项的简短原因。聊天里不每轮播报这些技术信息；在用户打开控制页或主动查询时展示。

### 4.3 情绪是可关闭的后续层

在表达和记忆验收稳定后，再增加短期情绪：按通道事件幂等更新、有界增量、按时间恢复、切换余量、最短保持时间及提示限频。先用少量可解释维度，不以类别数量作为质量指标。饱和、长期离线、时钟变化和重复回执都须有行为验收。

模型判定为可选项，沿用已批准的无工具 HTTP 适配器、独立预算和明确开关。不能借新插件改变模型、费用、凭据或真实调用安排；不能为了模仿效果建立后台 Agent 执行循环。模拟状态不能成为执行授权。

### 4.4 交付顺序与通过标准

| 顺序 | 可评审的交付 | 主要行为验收 |
| --- | --- | --- |
| 1 | 召回改进与本轮记忆回执 | 同义表达召回；最早/当前偏好区分；纠正优先；无关不注入；调高所有权重仍不串通道 |
| 2 | 场景回复偏好与预览 | 甜度/幽默有可观察变化；不机械套句；直接结果请求生效；失败与取消不被润色成成功 |
| 3 | 可选情绪状态及本机控制页 | 恢复、防抖、重复事件不叠加；状态与账号隔离；关闭可回退；现有人设快照不变 |

合成数据和模拟集成先行，再比较固定模型/强度下的多次回复。质量评价至少分开看召回率、无关注入率、纠正成功、身份一致性和表达自然度；显示了一组漂亮数值不算通过。外部插件成本、效果和测试数量均未在本机复现，不引用为本项目承诺。
