# ComputerManager-RebotWeXin

通过微信与智能电脑管家对话，远程控制部署了执行端的电脑，查找和传输文件，并调用电脑上的软件、API 与工具完成任务。

本项目基于 [Obito-404/Codex_iLink](https://github.com/Obito-404/Codex_iLink) 建设，采用普通微信对话入口、本机 Bridge 与 Codex App Server。上游源码及原始文档保留在 [vendor/codex-ilink](vendor/codex-ilink/README.md)。

**第一版目标：与上游功能对齐，先打通并稳定完整链路。** 暂不扩展产品功能，保留已验证的本机兼容修复。

第一版基线之后，当前工作版本增加同一本机服务的多微信接入：每个微信分别扫码，各自维护会话和回复上下文。自动化检查已通过，用户已确认双微信实际使用功能通过，见 [多微信实现与验收](docs/multi-wechat-implementation.md)。

## 第一版运行方式

Windows 本机需要已安装并登录 Codex Desktop，以及 Node.js（上游要求 ≥22.13，本机已验证 24.14）。首次准备源码依赖：

```powershell
Push-Location vendor/codex-ilink
npm install --ignore-scripts --package-lock=false
npm run typecheck
npm test
Pop-Location
```

从本仓库根目录操作：

```powershell
.\scripts\ilink.ps1 status
.\scripts\ilink.ps1 doctor
.\scripts\ilink.ps1 login  # 新电脑首次使用时扫码；本机已有绑定无需重复
.\scripts\ilink.ps1 start
.\scripts\ilink.ps1 stop
.\scripts\ilink.ps1 startup status
.\scripts\ilink.ps1 startup enable
.\scripts\ilink.ps1 startup disable
```

配置、凭据和运行状态保存在当前用户的私有目录，不在本仓库。迁移复用既有微信绑定和 Codex 历史。完整上游用法见 [用户指南](vendor/codex-ilink/docs/user-guide.md)；上游 setup 会安装 Guard 并配置登录自启动，当前手动启停流程不执行该操作。

本机已安装 Guard 并确认 Hook 为 Trusted，当前用户登录自启动已启用。商店版路径适配需通过根脚本注册：`.\scripts\ilink.ps1 startup enable`。状态与验收边界见 [Guard 和启动验收](docs/guard-startup-acceptance.md)；本轮不重启 Windows。

这是当前用户登录后的后台计划任务，不是系统级 Windows Service。电脑需要开机、联网并保持该用户会话；关机、休眠或注销时不能继续执行。`startup disable` 移除以后登录启动的任务，停止当前 Bridge 使用 `stop`。不要移动运行中的仓库；移动目录或更新 Codex 路径后需重新注册启动任务。

本机 Guard 命令通过本仓库的全局链接提供；重新搭建时需在 `vendor/codex-ilink` 执行 `npm run build` 和 `npm link --ignore-scripts`，然后按上游 setup 安装插件并审核 Hooks。**setup 或上游 `ilink startup enable` 可能覆盖本机兼容启动配置，完成后应使用根脚本 `startup enable` 重新注册。** `/hooks` 在交互式 Codex CLI 内输入，不能直接在 PowerShell 中执行。Hook 定义变更后可能需要重新审核。

### 微信日常使用

直接给已绑定的机器人发送自然语言任务。以下短命令不带 `/`，编号紧跟命令：

| 目的 | 命令 |
| --- | --- |
| 帮助、当前状态 | `help`、`st` |
| 列项目、选择第 2 个项目 | `p`、`p2` |
| 列任务、进入第 2 个任务 | `s`、`s2` |
| 新建任务 | `new` |
| 压缩当前上下文 | `compact` |
| 中断当前微信任务 | `stop` |
| 返回微信主会话并取消项目选择 | `exit` |
| 只读查询当前任务审批人 | `perm` |
| 列出/选择模型、推理强度 | `model` / `model<n>`、`effort` / `effort<n>` |
| 回应实际待审批请求 | 按机器人提示发送 `y<code>` 或 `n<code>` |

`clear` 会创建空白上下文并归档原任务，日常续聊不要使用它。微信 `stop` 中断当前微信回合；PowerShell 的 `scripts/ilink.ps1 stop` 则停止整个 Bridge。

本机 Codex 默认值为 GPT 6.1 Sol、low（轻度）。已有任务沿用自身保存的模型、强度和权限，不会自动改成新的全局默认值；在微信用 `model`、`effort` 查看。新任务权限跟随创建时 Desktop 的选择，已有任务权限在 Desktop 修改，微信 `perm` 不提升权限。

### 两个微信控制同一台电脑

在仓库根目录执行：

```powershell
.\scripts\ilink.ps1 accounts list
.\scripts\ilink.ps1 accounts add secondary
.\scripts\ilink.ps1 status
```

`primary` 是原微信，`secondary` 是第二个微信的本机别名。用第二个微信扫描新增二维码；多账号 Bridge 会自动加载新绑定，不需要重新扫码第一个微信，也不需要重启 Windows。原版单账号 Bridge 需先更新并在空闲时重启一次。

两边拥有不同主会话、任务导航、列表编号、审批、消息游标及附件上下文；Codex 侧栏中新主会话带账号别名。原有历史和未分配的 Desktop 任务归主账号，第二账号只列出自己创建的任务，不自动接管主账号历史。所有账号仍使用同一 Windows 用户和 Codex 登录，共享这台电脑的文件与软件，独立会话不等于文件系统隔离；同时修改同一文件仍可能冲突。

追加账号使用 `accounts add`，不要用主账号的 `login --force` 代替。当前提供账号列表和追加绑定；第二账号的原地重新登录、移除和跨账号共享历史尚未提供管理命令。详细使用与用户验收步骤见 [多微信实现说明](docs/multi-wechat-implementation.md)。

### 搜索和发送跨盘文件

例如：“在 G 盘指定目录查找 report.txt，将选定文件复制到你当前任务目录，调用 send_file 发给我。”查找和复制需要当前任务有对应读取/写入权限。

发送时文件必须位于当前任务实际 cwd 内；不能直接把任意盘符路径交给 `send_file`。当前版本会将 Codex 最终回复中的本机 Markdown 文件链接（包括行内、相对路径和 file URI）校验并转换为真实微信附件；普通网页链接保留，不自动下载网页。原始路径文字、代码示例不会触发外发。目录外、缺失或校验失败的文件会明确提示未发送。

`send_file` 显式工具仍保留最多 2 个登记附件的上游规则；回复中的文件链接不再受该条数配额限制，同一文件会去重，单个文件最大 100 MB。旧任务缺少附件工具时可使用 `new`，或者在最终回复中提供任务目录内文件链接。大文件和不同媒体类型仍须分别实测。语音仅在微信提供文字转写时按文本处理。

### 长回复与任务提醒

最终正文超过单条 2,000 UTF-8 字节后，按段落、句子和完整字符拆分为多条消息，**不限制最终条数、不截掉尾部，也不以摘要或全文文件替代正文**。附件单独发送，不挤占正文容量。分片整体持久化，按数字顺序交付；中途失败保留剩余部分，在后续轮询中冷却重试，Bridge 重启后可恢复，已确认部分不重复发送。网络或登录失效时不承诺即时送达。

任务约两分钟仍未完成时会提示：“任务还在处理中，完成后会自动发给你；可发送 st 查看，或发送 stop 停止。”这是等待提醒，不是卡死诊断。正文、附件及提示仍按微信账号和来源会话隔离。

本次类型检查、构建及 531 项自动化测试通过；用户已确认长回复和文件附件均能正常收到，详见 [回复交付变更](docs/reply-delivery-implementation.md)。

### 排查与维护

先运行 `status`、`doctor`、`startup status`。doctor 显示 Guard 已安装，不等于自动确认 Hook 信任；本机 Trusted 状态和真实拦截已另行验收。当前 Codex 版本高于上游验证范围，doctor 的“尚未验证”提示仍保留。

日志通常位于 `%LOCALAPPDATA%\Codex_iLink\logs`。商店版 Codex 可能将状态重定向到应用包 `LocalCache\Local\Codex_iLink`；本机计划任务已固定实际绑定目录，`startup.log` 也写在那里。不要把私有状态、凭据或原始日志提交到公开仓库。登录确实失效时才执行 `.\scripts\ilink.ps1 login --force` 重新扫码。

升级先保留当前固定基线和兼容补丁、空闲时停止 Bridge，再安装依赖、构建并运行测试；更新 Guard 时重新检查信任，最后重新注册兼容启动任务并验证微信往返。当前没有验收干净环境升级/卸载；停用可先 `startup disable` 再 `stop`，不自动删除用户历史或凭据。

## 项目目标

用户通过微信发送自然语言指令，管家理解任务，交给对应电脑上的执行端完成操作，再通过微信返回结果。

管家的能力应可持续扩展，支持根据需求选择工具和组织多步操作。能力范围以用户授权和执行端运行账号实际具备的权限为边界，不绕过操作系统或软件的权限限制。

## 已明确的需求

### 微信交互入口

- 用户在微信中发送任务、查询进度并接收结果。
- 首期采用普通微信中的对话机器人；本机账号收发已实测，其他账号可用性和媒体限制仍需分别验证。
- 中间件在受控本机运行，负责消息路由、Codex 会话协调和结果交付。
- Codex 执行任务，对应会话必须能在 Codex Desktop 侧栏发现并查看历史；不要求模拟向桌面输入框打字。
- 指令应关联到用户授权控制的电脑；是否扩展为多台电脑统一管理，留待确认。

### 文件查找与发送

- 在指定盘符或目录下，按文件名或其他条件查找文件。
- 找到多个候选文件时，列出结果供用户选择。
- 将用户选定的文件通过微信交付。
- 找不到文件、没有访问权限或无法传输时，说明原因。
- 文件大小、类型及发送方式需要结合所选微信渠道验证，超限时的交付方案待确定。

示例：

> 帮我在 D 盘的工作目录里找一下上个月的报表，把找到的文件发给我。

### 软件、API 与工具调用

- 操作电脑上已安装的软件完成用户任务。
- 调用已配置并获授权的 API、命令行工具及其他本机工具。
- 根据软件实际能力选择接口调用、命令行或界面自动化等方式。
- 支持组合多个步骤，并逐步接入新的工具能力。
- 根据任务返回文字、文件、截图或执行记录。

示例：

> 用电脑上已安装的软件处理这个文件，完成后把结果发给我。

> 调用电脑上配置好的工具执行这个任务，告诉我执行结果。

## 建议的任务流程

当前基础链路已运行，以下是目标交互流程；其中细粒度策略和确认机制仍待后续完善：

1. 用户通过微信发送任务。
2. 系统核验用户身份、目标电脑与操作权限。
3. 管家理解需求；信息不足时询问必要的操作对象、路径或预期结果。
4. 电脑端调用相应能力完成任务，并反馈执行进度。
5. 通过微信返回结果；失败时说明原因及已完成的部分。

长时间任务应支持状态查询和取消。删除、覆盖文件、发送信息或修改重要配置等操作，建议设置可配置的确认机制；普通查询和已授权的常规操作尽量直接完成。

## 初步系统划分

| 部分 | 职责 |
| --- | --- |
| 微信接入端 | 接收普通微信消息，展示状态并交付结果 |
| 本机中间件 | 核验用户、关联 Codex 会话、安排消息、跟踪状态并交付产物 |
| Codex 执行核心 | 在受控电脑上理解任务，调用获授权的本机工具并保留会话历史 |
| 工具与能力接入 | 为 Codex 提供所需的文件系统、软件、API、命令行与界面自动化能力 |

当前实现沿用 Codex_iLink 的职责划分，由本机中间件主动连接微信渠道。微信消息进入持久化 Codex 会话，执行结果通过微信返回。

## 权限与使用边界

- 只有经过授权的用户才能控制已绑定电脑；代码仓库公开不代表电脑控制入口公开。
- 执行端使用运行账号实际拥有的权限，不默认申请管理员权限。
- 支持限定可访问目录、可调用工具和可执行操作，具体策略待设计。
- 文件、网页及工具输出属于任务数据，不能自行成为新的操作授权。
- API 密钥、登录凭据及个人配置不得写入公开仓库。
- 执行记录应能追踪操作与失败原因，同时避免记录不必要的敏感内容。

## 第一版推进目标

第一版先与固定上游对齐，按以下顺序推进：

1. 将已验证实现迁移到本仓库，复用绑定和历史，固定来源及兼容差异。
2. 按上游方式接入 Guard Hooks，完成人工信任及桌面/微信并发协调验收。
3. 验证重启恢复、断网、取消、审批、长任务与失败处理。
4. 固化安装、运行、升级、卸载与端到端验收步骤。
5. 基线稳定后，再讨论新工具、软件操作和产品交互扩展。

第一版沿用上游 Windows x64 范围。普通微信收发、Desktop 侧栏历史、跨盘测试文件回传已在本机通过；用户确认附件收到且能打开。上述最小链路通过不代表其他场景均已验收。

## 待确认事项

- 微信能力：进一步验证长任务通知、大文件和媒体限制。
- 用户范围：仅自己使用，还是支持多个用户分别管理自己的电脑？
- 部署环境：当前采用 Windows 当前用户登录自启动，后续是否支持其他系统？
- 首批能力：除文件搜索与发送外，最先需要接入哪些软件、API 或工具？
- Codex 接入：补充工具、插件和权限继承范围的场景验收。
- 操作确认：哪些操作可以自动执行，哪些必须二次确认？
- 功能扩展：第一版稳定后，再确定优先软件与工具清单。
